# Legacy brand compatibility allowlist
# =============================================================================
# Effective 31 July 2026 the product was renamed NanoCloud -> NubArca.
#
# The identifiers below still carry the former name because renaming them would
# break something real: a running deployment, a stored row, a signed token, an
# installed app's upgrade path, or the historical record. They are collected HERE
# rather than scattered through the tree, and scripts/check-brand-cleanliness.sh
# fails on any occurrence of the former name that does not match an entry.
#
# Adding an entry is deliberate. Every entry MUST state all five fields.
#
# FORMAT — one block per entry, blank line between blocks:
#
#   [entry]
#   identifier:  human-readable name of the thing
#   match:       Python regex; a source line matching it is allowed
#   paths:       optional, comma-separated fnmatch globs limiting where it applies
#                (omit to allow the identifier anywhere)
#   why:         why it must remain
#   breaks:      what breaks if it is renamed
#   remove-when: the condition under which this entry can be deleted
#
# Lines starting with # are comments. Field order inside a block is free.
# =============================================================================


# -----------------------------------------------------------------------------
# 1. The .NET assembly, and everything derived from its name
# -----------------------------------------------------------------------------
# DECISION GATE (see docs/brand.md and the rename report): renaming the solution,
# projects and namespaces to NubArca.* was investigated and REJECTED for now.
#
#   safe if renamed:   persisted job types are short dotted strings
#                      ("media.video.hls.generate"), never assembly-qualified;
#                      EF migration IDs in __EFMigrationsHistory are timestamps
#                      plus a name and carry no brand; ASP.NET Data Protection
#                      never calls SetApplicationName, so its discriminator is
#                      the content-root path (/app), not the assembly;
#                      auth cookie names are literal string constants.
#   NOT safe:          the assembly name IS the container entrypoint
#                      (ENTRYPOINT ["dotnet", "NanoCloud.Api.dll"]) and is baked
#                      into every production runbook command
#                      ($DC exec api dotnet NanoCloud.Api.dll ...), the deploy
#                      scripts and the operator's muscle memory. Proving that
#                      rename safe requires a deploy, which this work forbids.
#
# The user-visible consequence was removed separately: the OpenAPI document title
# is now set EXPLICITLY to "NubArca API", where it previously defaulted to the
# assembly name and leaked the old brand to every API consumer.
#
# This is treated as ONE compatibility unit: identifiers inside the assembly keep
# the legacy prefix coherently rather than producing a half-renamed namespace.

[entry]
identifier:  .NET solution, project, namespace and assembly name
match:       NanoCloud\.(Api|sln)|NanoCloud\.Api\.(Tests|dll|csproj)|namespace NanoCloud|using NanoCloud|NanoCloud\.Api\.Tests
why:         The assembly name is the produced DLL name and therefore the container entrypoint and every documented operator command.
breaks:      docker entrypoint fails to start; every `$DC exec api dotnet NanoCloud.Api.dll ...` runbook command breaks; deploy scripts and monitoring break.
remove-when: A coordinated release renames the assembly, the Dockerfile ENTRYPOINT, deploy/, CLAUDE.md and docs together, and is verified on the production host.

[entry]
identifier:  DI registration extension methods on the retained assembly
match:       AddNanoCloud(Plates|Aesthetics|JobHandlers)
paths:       src/**,tests/**
why:         Internal to the retained assembly; renaming only these would leave a half-renamed namespace, which the brand policy forbids.
breaks:      Nothing at runtime — but it produces exactly the "mixed arbitrary namespaces" state the policy prohibits.
remove-when: The assembly rename above happens; these go with it.

[entry]
identifier:  Stack-frame marker used by log-leak guards in tests
match:       "at NanoCloud|at NanoCloud\\.
paths:       tests/**
why:         Asserts that no stack trace from our own assembly reaches a response or log; the marker must match the real frame prefix.
breaks:      The leak guards stop matching real frames and silently pass, removing a security regression net.
remove-when: The assembly rename above happens.


# -----------------------------------------------------------------------------
# 2. Authentication — persisted in every user's browser and on every paired TV
# -----------------------------------------------------------------------------

[entry]
identifier:  Session cookie names NanoCloud.Auth and NanoCloud.TvSession
match:       NanoCloud\.(Auth|TvSession)
why:         The cookie name is the wire contract with every browser and paired TV device that currently holds a session.
breaks:      Renaming invalidates every live session: all users signed out, all TVs unpaired. Explicitly excluded from this work.
remove-when: A release that deliberately accepts a global sign-out, or one that reads both names during a migration window.


# -----------------------------------------------------------------------------
# 3. Persisted database and blob-storage values
# -----------------------------------------------------------------------------

[entry]
identifier:  Logical container key prefixes for Plates and Aesthetics
match:       __nanocloud_(plates|aesthetics)_
why:         Written into existing rows as the logical container key; the prefix is how those rows are found.
breaks:      Every existing plate and aesthetics container is orphaned — the rows survive but nothing resolves them.
remove-when: A data migration rewrites the stored keys, with rollback and a verified dry run.

[entry]
identifier:  Hash peppers and the party-token signing secret fallback
match:       nanocloud-(deleted-content-dev-pepper-v1|plates-dev-pepper-v1|aesthetics-dev-pepper-v1|party-token-secret-v1|test-sha256)
why:         These strings are inputs to persisted hashes and to issued token signatures.
breaks:      Existing tombstone fingerprints, container-key hashes and outstanding public party tokens all stop validating.
remove-when: Never for the peppers without a rehash migration; the party secret is already overridable by configuration in production.

[entry]
identifier:  Database, role and default connection-string values
match:       Database=nanocloud|Username=nanocloud|POSTGRES_(DB|USER|PASSWORD)[=:]\s*nanocloud|pg_isready.*nanocloud|\.With(Database|Username|Password)\("nanocloud"\)|"Postgres":.*nanocloud
why:         The live production database, its role and its password are named this.
breaks:      The API cannot connect; a renamed database would be an empty second database, which this work explicitly forbids creating.
remove-when: Never for branding alone.


# -----------------------------------------------------------------------------
# 4. Container, volume, network and filesystem identity
# -----------------------------------------------------------------------------

[entry]
identifier:  Docker container names, networks, image tags and named volumes
match:       nanocloud-(postgres|api|worker|frontend|internal|nlu|human-aesexpert|openvino|tv-updates|storage|staging|dataprotection|derived|ort|native)[-a-z0-9:.]*
why:         Named volumes hold the live Postgres data, the blob store, the Data Protection keys and the TV update payloads.
breaks:      Renaming a volume detaches the running stack from its data — an empty database and an empty blob tree. Explicitly forbidden by this work.
remove-when: Never for branding alone.

[entry]
identifier:  Persistent filesystem paths inside containers and on the host
match:       /(var/lib|opt|srv|var/cache|mnt/raid1)/nanocloud|/srv/nanocloud-models|/opt/nanocloud
why:         Blob storage, staging, Data Protection keys, model roots and the deployment checkout live at these paths.
breaks:      Storage is remounted at a path with no data; the API sees an empty library.
remove-when: Never for branding alone.

[entry]
identifier:  Backup archive directory naming
match:       nanocloud-\$|nanocloud-%|nanocloud-[0-9]{8}T|nanocloud-YYYYMMDD
paths:       deploy/**
why:         Existing backup archives on disk are named with this prefix and restore.sh locates them by it.
breaks:      Previously taken backups become undiscoverable by the restore script.
remove-when: A restore script that accepts both prefixes ships and the old archives have aged out.


# -----------------------------------------------------------------------------
# 5. Operator-configured environment variable names
# -----------------------------------------------------------------------------

[entry]
identifier:  NANOCLOUD_* and NANO_CLOUD_* environment variables
match:       NANO_?CLOUD_[A-Z0-9_]*\*?
why:         Operators have these set in the production .env, in CI and in the TV build environment.
breaks:      Configuration silently reverts to defaults — wrong device placement, missing API base URL, broken OTA, no admin bootstrap.
remove-when: A release reads both spellings for one deployment cycle, then drops the old one after the fleet is confirmed migrated.

[entry]
identifier:  Plates face-redaction provider enum member, parsed from configuration
match:       ExistingNanoCloud(FaceDetector|PlateFaceBoxDetector)
why:         Operators set Plates:FaceRedaction:Provider=ExistingNanoCloudFaceDetector in .env; the value is parsed by name.
breaks:      Existing .env files stop selecting the provider and fall back, changing redaction behaviour silently.
remove-when: The parser accepts both names for a deployment cycle.


# -----------------------------------------------------------------------------
# 6. Client applications — installed identity
# -----------------------------------------------------------------------------

[entry]
identifier:  Android applicationId it.littlefly.nanocloudtv
match:       it\.littlefly\.nanocloudtv|nanocloudtv
why:         The Android package id is the installed app's identity.
breaks:      NubArca TV installs as a SEPARATE application beside the old one, with no upgrade path and no data. Explicitly forbidden by this work.
remove-when: An explicit store migration is planned; there is no in-place rename for an Android applicationId.

[entry]
identifier:  Expo project slugs nanocloud-tv and nanocloud-mobile
match:       nanocloud-(tv|mobile)\b
why:         The slug is part of the EAS project / OTA update identity that shipped devices resolve against.
breaks:      Deployed TVs stop finding their OTA channel.
remove-when: A coordinated EAS project migration, with a build that shipped before the change no longer in the field.

[entry]
identifier:  TV session storage key nanocloud.tv.session.cookie
match:       nanocloud\.tv\.session\.cookie|"nanocloud\." prefix
why:         Persisted in AsyncStorage on every paired TV.
breaks:      Every paired TV is signed out and must be re-paired by hand.
remove-when: A TV release that reads the old key once and migrates it, after the fleet has taken that release.

[entry]
identifier:  Published TV APK filename and its public download route
match:       nanocloud-tv\.apk
why:         A public, externally linked download URL, plus the matching .sha256 route and the publish script's remote name.
breaks:      Existing links and QR codes 404; the sideload instructions people already have stop working.
remove-when: The frontend serves both names and the old one has stopped receiving traffic.

# 7. Browser storage keys read once during migration
# -----------------------------------------------------------------------------

[entry]

match:       nanocloud\.(theme|lang|nav\.collapsed)
paths:       frontend/**
why:         Read only when the nubarca.* key is absent, migrated, then deleted — so nobody loses a theme or language choice to the rename.
breaks:      Every existing reader silently reverts to the dark/Italian defaults.
remove-when: The fleet has rolled over; the fallback branch and these keys can then be deleted together.

[entry]
identifier:  Pre-rebrand photo-export destination folder
match:       NanoCloudExport
paths:       frontend/**

breaks:      A cosmetic rename silently re-downloads the reader's entire photo library into a new folder.
remove-when: The fallback has been in the field long enough that no unmigrated export folders remain.

# -----------------------------------------------------------------------------
# 10. Historical record — never rewritten
# -----------------------------------------------------------------------------
# Changelog entries, release notes, migration history and the design documents
# that describe past work keep the name they were written with. Rewriting them
# would make the record inaccurate. Current installation and user documentation
# uses NubArca; see docs/brand.md.

[entry]
identifier:  Historical documentation, changelog and operational runbooks
match:       .
paths:       CHANGELOG.md,docs/**,deploy/**.md,.claude/**,.codex/**,tv/README.md
why:         Historical accuracy, plus runbooks that must quote live infrastructure identifiers (volumes, paths, entrypoint commands) verbatim to remain usable. README.md, ARCHITECTURE.md, CLAUDE.md, ROADMAP.md, AGENTS.md and DEVELOPMENT_STATE.md are deliberately NOT here: they describe the current product and are held to the new name.
breaks:      A runbook that names a volume or command incorrectly is worse than one that names it with the legacy spelling.
remove-when: Never for history. Runbook identifiers follow whenever the underlying identifier is migrated.

[entry]
identifier:  EF Core migration history
match:       .

why:         Migration classes and their model snapshots are an append-only historical record keyed by identifiers already applied in production.
breaks:      Rewriting a shipped migration diverges source from the __EFMigrationsHistory table; EF can no longer reconcile the model.
remove-when: Never.

[entry]
identifier:  The rebrand's own tooling, tests and documentation
match:       .
paths:       assets/brand/**,scripts/generate-brand-assets.py,config/legacy-brand-compatibility.txt,scripts/check-brand-cleanliness.sh,docs/brand.md,frontend/src/brand/brand.test.tsx,frontend/src/storage/brandedStorageKey.ts,frontend/src/theme/themePreference.ts,frontend/src/theme/themePreference.test.ts,frontend/src/theme/themeBootstrap.test.ts,frontend/src/i18n/i18n.test.tsx,tests/NanoCloud.Api.Tests/Branding/**

breaks:      The checker could not describe what it allows, and the tests that prove the old name is gone could not reference it.
remove-when: Never.
