# Legacy brand compatibility allowlist
# =============================================================================
# Effective 31 July 2026 the product was renamed NanoCloud -> NubArca.
#
# The identifiers below still carry the former name because renaming them would
# break something real: a running deployment, a stored row, a signed token, an
# installed app's upgrade path, or the historical record. They are collected HERE
# rather than scattered through the tree, and scripts/check-brand-cleanliness.sh
# fails on any occurrence of the former name that does not match an entry.
#
# Adding an entry is deliberate. Every entry MUST state all five fields.
#
# FORMAT — one block per entry, blank line between blocks:
#
#   [entry]
#   identifier:  human-readable name of the thing
#   match:       Python regex; a source line matching it is allowed
#   paths:       optional, comma-separated fnmatch globs limiting where it applies
#                (omit to allow the identifier anywhere)
#   why:         why it must remain
#   breaks:      what breaks if it is renamed
#   remove-when: the condition under which this entry can be deleted
#
# Lines starting with # are comments. Field order inside a block is free.
# =============================================================================


# -----------------------------------------------------------------------------
# 1. The .NET assembly, and everything derived from its name
# -----------------------------------------------------------------------------
# DECISION GATE (see docs/brand.md and the rename report): renaming the solution,
# projects and namespaces to NubArca.* was investigated and REJECTED for now.
#
#   safe if renamed:   persisted job types are short dotted strings
#                      ("media.video.hls.generate"), never assembly-qualified;
#                      EF migration IDs in __EFMigrationsHistory are timestamps
#                      plus a name and carry no brand; ASP.NET Data Protection
#                      never calls SetApplicationName, so its discriminator is
#                      the content-root path (/app), not the assembly;
#                      auth cookie names are literal string constants.
#   NOT safe:          the assembly name IS the container entrypoint
#                      (ENTRYPOINT ["dotnet", "NanoCloud.Api.dll"]) and is baked
#                      into every production runbook command
#                      ($DC exec api dotnet NanoCloud.Api.dll ...), the deploy
#                      scripts and the operator's muscle memory. Proving that
#                      rename safe requires a deploy, which this work forbids.
#
# The user-visible consequence was removed separately: the OpenAPI document title
# is now set EXPLICITLY to "NubArca API", where it previously defaulted to the
# assembly name and leaked the old brand to every API consumer.
#
# This is treated as ONE compatibility unit: identifiers inside the assembly keep
# the legacy prefix coherently rather than producing a half-renamed namespace.

[entry]
identifier:  .NET solution, project, namespace and assembly name
match:       NanoCloud\.(Api|sln)\b|NanoCloud\.Api\.(Tests|dll|csproj)\b
# NARROWED: this previously also carried bare `namespace NanoCloud` and
# `using NanoCloud` alternatives, which matched any English sentence
# containing "using NanoCloud" — e.g. "Start using NanoCloud today." Every
# real declaration in src/ and tests/ is dotted (NanoCloud.Api.*), so the
# dotted forms above already cover them and the bare ones only widened the
# rule. The self-test pins both directions.
why:         The assembly name is the produced DLL name and therefore the container entrypoint and every documented operator command.
breaks:      docker entrypoint fails to start; every `$DC exec api dotnet NanoCloud.Api.dll ...` runbook command breaks; deploy scripts and monitoring break.
remove-when: A coordinated release renames the assembly, the Dockerfile ENTRYPOINT, deploy/, CLAUDE.md and docs together, and is verified on the production host.

[entry]
identifier:  DI registration extension methods on the retained assembly
match:       AddNanoCloud(Plates|Aesthetics|JobHandlers)
paths:       src/**,tests/**
why:         Internal to the retained assembly; renaming only these would leave a half-renamed namespace, which the brand policy forbids.
breaks:      Nothing at runtime — but it produces exactly the "mixed arbitrary namespaces" state the policy prohibits.
remove-when: The assembly rename above happens; these go with it.

[entry]
identifier:  Stack-frame marker used by log-leak guards in tests
match:       "at NanoCloud|at NanoCloud\\.
paths:       tests/**
why:         Asserts that no stack trace from our own assembly reaches a response or log; the marker must match the real frame prefix.
breaks:      The leak guards stop matching real frames and silently pass, removing a security regression net.
remove-when: The assembly rename above happens.

# 2. Authentication — persisted in every user's browser and on every paired TV
# -----------------------------------------------------------------------------

[entry]
identifier:  Session cookie names NanoCloud.Auth and NanoCloud.TvSession
match:       NanoCloud\.(Auth|TvSession)
why:         The cookie name is the wire contract with every browser and paired TV device that currently holds a session.

[entry]

breaks:      The API cannot connect; a renamed database would be an empty second database, which this work explicitly forbids creating.
remove-when: Never for branding alone.


# -----------------------------------------------------------------------------
# 4. Container, volume, network and filesystem identity
# -----------------------------------------------------------------------------

[entry]
identifier:  Docker container names, networks, image tags and named volumes
match:       nanocloud-(postgres|api|worker|frontend|internal|nlu|human-aesexpert|openvino|tv-updates|storage|staging|dataprotection|derived|ort|native)[-a-z0-9:.]*
why:         Named volumes hold the live Postgres data, the blob store, the Data Protection keys and the TV update payloads.
breaks:      Renaming a volume detaches the running stack from its data — an empty database and an empty blob tree. Explicitly forbidden by this work.
remove-when: Never for branding alone.

[entry]
identifier:  TV OTA signing-material directory on the build/publish host
match:       nanocloud-tv-ota
paths:       .env.example,docs/**.md,deploy/**

breaks:      Publication cannot find the signing key, and the documented bootstrap/rotation procedure points at a directory that does not exist.
remove-when: The operator moves the key material and updates .env in the same maintenance step.

[entry]
identifier:  Persistent filesystem paths inside containers and on the host
match:       /(var/lib|opt|srv|var/cache|mnt/raid1)/nanocloud|/srv/nanocloud-models|/opt/nanocloud
why:         Blob storage, staging, Data Protection keys, model roots and the deployment checkout live at these paths.
breaks:      Storage is remounted at a path with no data; the API sees an empty library.
remove-when: Never for branding alone.

[entry]
identifier:  Backup archive directory naming
match:       nanocloud-\$|nanocloud-%|nanocloud-[0-9]{8}T|nanocloud-YYYYMMDD
paths:       deploy/**
why:         Existing backup archives on disk are named with this prefix and restore.sh locates them by it.
breaks:      Previously taken backups become undiscoverable by the restore script.
remove-when: A restore script that accepts both prefixes ships and the old archives have aged out.

# nubarca-tv, storage key nubarca.tv.session.cookie and artifact nubarca-tv.apk.
#
# What legitimately REMAINS below: the backend TvSession cookie (a wire contract
# with /api/tv/*, not a user-visible name) and the NANOCLOUD_* operator
# environment variables, both covered by their own entries in sections 2 and 5.

[entry]
identifier:  Expo project slug nanocloud-mobile
match:       nanocloud-mobile\b
paths:       mobile/**,config/**,scripts/**
why:         The unshipped mobile app still carries this slug; the final mobile identity (slug nubarca, applicationId it.littlefly.nubarca) is reserved but not yet applied.
breaks:      Nothing today — the mobile app has no native project and no release. Kept so the slug is declared rather than silently tolerated.
remove-when: The mobile app takes its reserved NubArca identity, which is a separate slice from TV-ID-01.

[entry]
identifier:  Unadvertised nanocloud-tv.apk download alias
match:       nanocloud-tv\.apk

# -----------------------------------------------------------------------------
# 10. Historical record — never rewritten
# -----------------------------------------------------------------------------
# Changelog entries, release notes, migration history and the design documents
# that describe past work keep the name they were written with. Rewriting them
# would make the record inaccurate. Current installation and user documentation
# uses NubArca; see docs/brand.md.

# NARROWED. This was previously one rule with `match: .` over CHANGELOG.md,
# docs/**, deploy/**.md and tv/README.md, which permitted ARBITRARY old-brand
# prose anywhere in the documentation — it would have accepted a brand-new
# sentence like "NanoCloud is the current product." in docs/current-work.md.
# The 50 lines it was covering were audited: 33 were ordinary product prose and
# have been rebranded, and the 17 that genuinely had to stay are now matched by
# the specific rules below. No documentation rule uses a bare `.` any more.

[entry]
identifier:  The rename statement itself, in the records that announce it
match:       \*{0,2}NanoCloud\*{0,2} was renamed|renamed from \*{0,2}NanoCloud|NanoCloud\*{0,2} to \*{0,2}NubArca|keep their old .*NanoCloud.* spelling
paths:       CHANGELOG.md,tv/README.md,docs/brand.md
why:         A document cannot state that the product was renamed without naming what it was renamed from.
breaks:      "NubArca was renamed NubArca" — the sentence stops being true or even meaningful.
remove-when: Never; this is the historical record of the rename.

[entry]
identifier:  Historical release entries in the changelog
match:       ^NanoCloud `[0-9]
paths:       CHANGELOG.md
why:         Records what shipped under the name it shipped with. Anchored to the line start and a version literal so it cannot cover new prose.
breaks:      Rewriting a released entry makes the changelog claim a name that release never had.
remove-when: Never.

[entry]
identifier:  Repository clone directory in setup runbooks
match:       git clone [^\n]*nanocloud|cd nanocloud\b|<repo> nanocloud
paths:       deploy/**.md,docs/**.md
why:         `git clone` creates a directory named after the repository, which is still nanocloud pending BRAND-02.
breaks:      Every subsequent `cd` and relative path in the runbook points at a directory that does not exist.
remove-when: BRAND-02 renames the GitHub repository.

[entry]
identifier:  nginx site filename on the production host
match:       sites-(available|enabled)/nanocloud
paths:       deploy/**.md
why:         The site file is already installed under this name on the running host.
breaks:      The runbook edits and symlinks a file the operator does not have, leaving the real site untouched.
remove-when: The site file is renamed on the host during a maintenance window.

[entry]
identifier:  Backup archive glob quoted in runbooks
match:       backups/nanocloud-|nanocloud-\*
paths:       deploy/**.md
why:         Existing backup directories on disk carry this prefix; the restore commands locate them by it.
breaks:      The documented restore command matches no existing archive.
remove-when: The restore script accepts both prefixes and the old archives have aged out.

[entry]
identifier:  Database name in SQL maintenance commands
match:       (REINDEX|ALTER|VACUUM|ANALYZE) DATABASE nanocloud
paths:       docs/**.md
why:         The live database is named nanocloud; these are commands an operator pastes verbatim.
breaks:      The command errors with "database does not exist".
remove-when: Never for branding alone — see the database entry above.

[entry]
identifier:  Historical benchmark probe filename

paths:       docs/model-deployment/**
why:         A dated benchmark record naming the exact script that produced the numbers.
breaks:      The record no longer identifies what was actually run.
remove-when: Never; the measurement already happened under that filename.

[entry]
identifier:  TV OTA signing certificate subject

why:         Deployed TVs validate OTA manifests against a certificate issued with this exact subject.
breaks:      Regenerating the certificate with a new CN invalidates OTA trust on every device already in the field.

[entry]
